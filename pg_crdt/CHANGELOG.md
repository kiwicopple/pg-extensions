# Changelog

## Extension 0.0.1

The first release adds the **PN-Counter** and **collaborative text** in the schema `crdt`. The PN-Counter is a counter that goes up and down, which several writers can change independently and merge later. It is SQL and PL/pgSQL only, needs no superuser, and works with any Postgres 16, 17 or 18 client, driver or API layer.

- **Type.** The domain `crdt.pn` over `jsonb`, with a versioned envelope `{t, v, p, n}`. See [PN-Counter](docs/types/pn-counter.md).
- **Functions.** `pn_empty`, `pn_increment`, `pn_decrement`, `pn_value`, `pn_merge`, the aggregate `pn_merge_agg`, and `pn_is_valid`. `pn_value` is `IMMUTABLE`, so it works in generated columns and expression indexes. See [PN-Counter functions](docs/reference/pn.md).
- **Untrusted writers.** `pn_apply_delta(state, delta, replica)` applies a delta from a writer you do not trust. It rejects entries that belong to another replica and malformed deltas, and treats stale entries as no-ops, so retries succeed. See [Accept writes from untrusted clients](docs/guides/security.md).
- **Identity.** `current_replica_id()` is the default identity: a JWT claim from `request.jwt.claims` (`sub`, or the claim named by `crdt.replica_id_claim`), else the setting `crdt.replica_id`. Nothing assumes a platform or UUID ids. A replica id is any non-empty text without `:`, and a key may carry a device suffix (`alice:phone`). See [Replicas and identity](docs/guides/replicas-and-identity.md).
- **Install.** One SQL file, as a plain script, through pg_tle or with the control file. The install refuses a `crdt` schema that another role controls. See [Install](docs/install.md).
- **Collaborative text** (`ydoc_`). A plain-text sequence CRDT (YjsMod order) whose documents live in the extension's tables, one row per run of characters; an app's table references `crdt.ydoc_docs (uid)`. A document is named by a `text` id, like a replica id: `ydoc_create(id)` takes the id the client chooses (a UUID, a UUIDv7 or ULID, a room name, an app key; at most 256 bytes, no control characters) or makes a random UUID, and raises `23505` for an id that exists instead of returning the existing document, so a predictable id cannot be taken over. Every function takes the text id; the tables keep an internal `bigint`. Local edits by position (`ydoc_insert`, `ydoc_delete`), whole-text saves with a three-way diff against a base (`ydoc_set`, `ydoc_base`), sync between copies (`ydoc_ops_since`, `ydoc_merge`), an untrusted write path that accepts only the writer's own ids and enforces causal rules V0 to V7 (`ydoc_apply`), and maintenance (`ydoc_compact`, `ydoc_rejected_purge` to empty the log of refused waiting ops, `ydoc_drop`). `ydoc_version` raises `P0002` for a document that does not exist, like the writers; the readers `ydoc_value`, `ydoc_length` and `ydoc_base` return null. The tables have no grants: apps grant them to the owner of their `security definer` wrappers. With `create extension` they are marked for `pg_dump`. Promoted from `experiments/text-table`; the jsonb-column alternative (`yseq_`, `experiments/text-column`) stays an experiment. See [Collaborative text](docs/types/collaborative-text.md), the [guide](docs/guides/collaborative-text.md) and the [reference](docs/reference/ydoc.md).
- **Tests.** The specification in `test/spec/` covers the merge laws, convergence under shuffled, duplicated and stale delivery, concurrency, the install paths (including `drop extension` and `pg_dump` of the text tables) and the write paths for untrusted writers, on Postgres 16, 17 and 18. For text it adds differential tests against a JavaScript reference implementation (71 fixtures, 14 of them malicious, and the automerge-paper editing trace). See the [test suite](test/README.md).

Known limits: the counter's state grows with the number of replicas, no compaction for delta tables, text is plain text without a client library and keeps its tombstones, and no upgrade path yet. See [Limits](docs/reference/limits.md).

Dropping the extension, or the schema of a direct install, with `cascade` drops every column of type `crdt.pn`, with its data. Dropping the extension drops every text document. See [Install](docs/install.md#uninstall).

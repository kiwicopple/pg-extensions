<span id="what-it-is" />

`pg_permissions` is a pure SQL extension for Postgres 16, 17, and 18. Manage permissions from SQL or JavaScript, then use row level security (RLS) to enforce access when your application queries a table.

Read the [documentation overview](./overview/) for the project's purpose, goals, and how it fits into your application.

## Try it in a database

[Install the SQL file](./install/), then follow the [quickstart](./get-started/quickstart/). You will create a permission, protect a table, and verify what two users can see. The database.dev package is not published yet; direct installation is available.

For an existing application, use the [documentation map](./guide/) to find a task. Model guides keep SQL and JavaScript examples together. [Identity and request context](./integrations/identity/) covers direct Postgres connections, Supabase, and PostgREST.

## Look up a function

The SQL reference covers [shared functions](./reference/shared/), [RBAC](./reference/rbac/), [OpenFGA](./reference/openfga/), and [Cedar](./reference/cedar/). The [JavaScript reference](./reference/javascript/) maps client methods to those functions and explains results and errors.

[OpenFGA compatibility](./models/openfga/compatibility/), [Cedar compatibility](./models/cedar/compatibility/), [API limits](./reference/limits/), and [CEL support](./reference/cel/) describe the boundaries of the implementation. Application checks cannot see rules that exist only in RLS; database policies make the final decision about which rows a query returns.

## Design and evidence

The extension has separate APIs for RBAC, OpenFGA and Cedar, with shared identity and RLS integration. [Current architecture](./research/architecture/) explains the design and how future models can fit. The [Cedar design record](./research/designs/e-cedar/) has the oracle results and the measurements of the Cedar model.

The test suite includes OpenFGA cases and Cedar's own integration tests, and runs on Postgres 16, 17, and 18, including pg_tle installation in Docker. [Benchmark reports](./research/benchmarks/overview/) distinguish the current implementation from historical prototypes and describe the limits of the measurements. Hosted installation and broader production workloads remain unverified in that research.

For agents and other tools, the [Markdown index](./llms.txt) links to plain-text versions of the documentation, including both example languages.

## What it is

`pg_permissions` is an authorization extension written in pure SQL. One schema supports several permission models: RBAC
today, Zanzibar/FGA-style relationships (sharing, nested teams, parent inheritance), and attribute rules later. Policies
call it from inside row-level security, so the database enforces access, not the app.

## Status

<CardGrid>
	<Card title="Design D is the extension" icon="approve-check">
		`pg_permissions--0.0.1.sql` is design D: `rbac_*` tables and an OpenFGA-compatible `fga_*` model. It passes the

	</Card>
	<Card title="Benchmarked on identical data" icon="rocket">
		Serial pgbench runs at 10k, 100k and 1M documents, three team shapes. Every read policy returns identical
		visible-document sets on every engine.
	</Card>
	<Card title="Not yet measured" icon="warning">
		pg_tle installs, concurrency beyond 4 clients, and Postgres versions other than 16, 17 and 18. See the [Postgres versions](./benchmarks/postgres-versions/) page for what exists.
	</Card>
</CardGrid>

## The three prototypes at a glance (history)

<EngineCards />

The headline: RBAC is a wash, with every engine within about 0.2 ms. The choice only mattered once an app graduates to
per-object sharing, where the engines trade read cost against nesting cost and complexity; D's numbers are on the [design D report](./benchmarks/design-d-report/).
